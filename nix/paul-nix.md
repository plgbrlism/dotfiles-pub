# My Nix Config — How It's Organized

So I finally got my NixOS config squared away using the official docs. Here's how everything's laid out and why.

---

## The Big Picture

```
nix/
├── flake.nix          ← the entry point, pulls everything together
├── home/              ← user-level stuff (my dotfiles, shell, git)
├── hosts/             ← machine-specific config (my HP laptop)
└── modules/           ← the good stuff — each file handles one thing
```

Think of it like this: **flake.nix** is the conductor, **hosts/** says "which machine," **modules/** says "what's on it," and **home/** says "how I use it."

---

## Folder Breakdown

### `flake.nix` — The Glue

| What it does | Why it matters |
|---|---|
| Single entry point for the whole system | One command rebuilds everything |
| Pulls nixpkgs 26.05, home-manager, nixos-hardware | Pins versions so nothing random breaks |
| Defines `nixosConfigurations.hp` | Tells Nix "this config is for my HP laptop" |
| Wires host config + home-manager user "paul" | Connects system-level and user-level together |

---

### `home/` — My User Layer

| File | What's in it | Why it's here |
|---|---|---|
| `default.nix` | Username, EDITOR, terminal packages, imports the others | Sets up my identity and brings in the rest |
| `shell.nix` | Zsh, starship prompt, aliases | All my shell customizations in one place |
| `git.nix` | Git + lazygit declarative config | Git setup that's version controlled, not scattered |
| `dotfiles.nix` | Symlinks dotfiles-pub + dotfiles-priv → ~/.config | Keeps app configs out of Nix but still managed |

**The dotfiles trick:** I keep app configs (like Alacritty, Neovim, etc.) in separate repos (`dotfiles-pub` for public stuff, `dotfiles-priv` for secrets). Nix just symlinks them into `~/.config` — clean separation, no secrets in the public repo.

---

### `hosts/` — Machine Definitions

| File | What it does |
|---|---|
| `configuration.nix` | Imports all modules, sets hostname, user, locale — the "what's on this machine" file |
| `hardware-configuration.nix` | Auto-generated by NixOS — lists kernel modules, partitions, CPU platform |

Right now there's just `hp/` (my HP Notebook 14-ck0115tu), but if I ever get another machine, I'd add a new folder here.

---

### `modules/` — The Real Power

Each file = one concern. No cross-imports between modules — flat and explicit. This is where the modularity shines.

| Module | What it handles |
|---|---|
| `boot.nix` | systemd-boot, kernel params, LTS kernel |
| `hardware.nix` | Intel microcode, GPU drivers (iHD/VA-API), 32-bit GL |
| `networking.nix` | NetworkManager + iwd, firewall (KDE Connect ports) |
| `audio.nix` | PipeWire stack (ALSA, PulseAudio, JACK, WirePlumber) |
| `desktop.nix` | X11, ly display manager, libinput, picom, XDG portals |
| `window-managers.nix` | i3 (X11), SwayFX, Niri (Wayland), shared WM utils |
| `fonts.nix` | Noto, DejaVu, Nerd Fonts, fontconfig fallbacks |
| `virtualisation.nix` | Docker + docker-compose, weekly auto-prune |
| `power.nix` | Powertop, zram swap (50% — important for my 4GB RAM) |
| `programmes.nix` | Git, editors, CLI tools, build toolchains, libs |
| `packages.nix` | Browsers, media, office, design, file management |
| `services.nix` | Bluetooth, fwupd, dbus, udisks2, polkit |

## Why This Setup Works

**Modularity means:**
- Want to disable Bluetooth? Comment out `services.nix` import. Done.
- Need to tweak boot params? Edit `boot.nix` only. Nothing else touches it.
- Adding a new machine? Copy `hosts/hp/`, change hardware config, done.
- Testing something sketchy? Isolate it in its own module first.

**No cross-module imports** — each module is self-contained. `audio.nix` doesn't care about `networking.nix`. They're friends, not spouses.

**User vs System separation** — `home/` is me, the user. `modules/` is the machine. Nix handles both layers, but they don't get tangled up.

---

## My Hardware Context

This config is tuned for an **Intel Celeron N4000 with 4GB RAM** — low power, not much headroom. That's why you see:
- No shadows in picom
- Bluetooth `powerOnBoot = false` (saves power)
- Zram swap at 50% (4GB isn't much)
- Powertop for power management
- Dual session: i3/X11 or SwayFX/Niri/Wayland — pick your fighter

## The Workflow

```bash
# Rebuild system
sudo nixos-rebuild switch --flake .#hp

# That's it. flake.nix orchestrates everything.
```

One command. Every module gets imported. Every home-manager setting applied. No manual steps, no "did I forget to restart something."
